# Workflow and reporting

* Using AI:
    - You can use the tools and models of your choise.
    - For starters, you can use Copilot with Gemini 3 Flash. (available with Copilot Pro - free for students)

## Workflow

* Generally, I will provide you with information about the problems you are to solve.
* Then, you go through the following process (for each function)
    - you can collaborate, or work individually and compare results later, but you need to have at least some discussion with peers.

### PLANNING

* first, try sketching out pseucode
    - how would you instruct a computer to solve this?
    - think about inputs, logic, and outputs.
    - use your own language, but try to be precise

### IMPLEMENTATION and TESTING

* next, try writing some code by hand
    - implement one function
    - and at least one test for that function
* Use AI
    - you can use AI to generate code and tests
    - or, you can use AI to review the code and tests you've written.

### REVIEW

* for each test, trace the execution of your code.  
    - if you used AI, check that you understand each line.
* Now you should discuss your results with your peers.  
    - take turns explaining functions and tests to one another.

### RETROSPECTIVE

* Please summarize your use of AI
    - what tools / models did you use?
    - what methods / prompts did you use?
* reflection:
    - how did your process compare with your peers?
    - how will you do things differently next time?

## Submission

Each INDIVIDUAL submits these three files:

* **single-file report**, including:
    - your initial pseudocode for 2-3 problems
    - information about the model and prompt(s) you used
    - summary of group discussions.
    - link to OneDrive folder:
        * **code file(s)**: python code and tests

Note:

* the group only needs to prepare one discussion summary 
    - but each individual in the group should add this to their report

### Grading Rubric (20 Points)

| Criteria | Points | Proficient (Full Credit) | Developing (Partial Credit) |
| :--- | :---: | :--- | :--- |
| **Planning** | 5 | **Precise Pseudocode:** Clear logic for 2–3 problems sketched in "own language" before AI use. Identifies inputs, logic, and outputs. | Pseudocode is vague, missing for required problems, or appears to be "back-written" from the Python code. |
| **Implementation & Testing** | 5 | **Hand-written & AI-assisted:** Includes both hand-written logic and AI-generated code/tests. All functions have at least one working test. | Code is missing tests, or there is no evidence of the hybrid hand-written/AI workflow. |
| **Review** | 5 | **Verification & Peer Interaction:** Detailed summary of group discussions and evidence of "tracing" code (explaining how lines work). | Group summary is superficial (e.g., "we liked it"). No evidence of peer explanation or line-by-line understanding. |
| **Retrospective** | 5 | **AI & Process Reflection:** Explicitly names tools (e.g., Gemini 3 Flash) and prompts. Reflects on peer comparisons and future changes. | Reflection is missing tool specifics, prompts, or fails to compare personal process with peer workflows. |
